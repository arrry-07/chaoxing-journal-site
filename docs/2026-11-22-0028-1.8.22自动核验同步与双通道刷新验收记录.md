# 2026-11-22 1.8.22 自动核验同步、同源 `release.json` 双通道兜底与驻留刷新验收记录

## 1. 背景与目标

为解决 GitHub 匿名接口（`api.github.com`）限流或暂不可达时，官网静态回退版本滞后及长驻标签页不能自动感知新版本的问题，在保持零第三方 npm 依赖、严格 CSP 与 SHA-256 真实性红线的前提下，本次为 `chaoxing-journal-site` 实施了三层闭环能力：

1. **全自动核验同步链路**（`scripts/sync-release.js` + `.github/workflows/sync-release.yml`）：支持每 30 分钟巡检、`repository_dispatch`（`app-release-published`）及手动触发；发现新正式版时真实流式下载完整 APK 与同版本 `SHA256SUMS.txt`，在确认「实际下载字节数 + 本地重算 SHA-256 + GitHub API `apk.digest` + `SHA256SUMS.txt` 对应文件名行」四方完全一致后，同步更新 `scripts/release-store.js`、`release.json`、`index.html` 与 `README.md`，跑通全量校验并直接打包发布 GitHub Pages。
2. **同源 `release.json` 双通道兜底**（`scripts/release-store.js`）：新增 `parseSiteReleaseManifest` 与 `resolveLatestRelease`，优先读取 `RELEASE_API`，失败且未主动中止时读取同源 `./release.json`（`cache: 'no-store'`）；仅当清单版本严格高于页面内嵌 `FALLBACK_RELEASE.version` 时无缝升级，否则诚实回退为 `isFallback: true`。同时优化 `applyRelease`（通过 `WeakMap` 比对 `{ version, checksum, isFallback }` 保持非空 `[data-copy-status]` 幂等）。
3. **页面驻留节流刷新**（`scripts/site.js`）：结合首屏加载、切回可见页（60 秒节流）、网络 `online` 恢复（5 秒节流）与可见态 5 分钟轮询静默刷新，并在切入后台或 `pagehide` 时清理定时器与中止挂起请求。

## 2. 本轮发现并修复的额外真实问题

1. **`index.html` CSP `connect-src` 同源拦截修复（经用户确认）**：按 W3C CSP 规范，显式声明 `connect-src https://api.github.com;` 时不会回退继承 `default-src 'self'`，实测 Chrome 会直接拦截 `fetch('./release.json')`。经用户确认授权后，将 `index.html` 第 6 行最小化补充为 `connect-src 'self' https://api.github.com;`（仅放行同源与 `api.github.com`），并在 `scripts/check-site.js` 补充对应 CSP 断言。
2. **`scripts/site.js` 导航高亮 `IntersectionObserver` 陈旧坐标修复**：浏览器验收期间发现从 `#guide` 点击跳转 `#notes` 时，`aria-current="location"` 偶发/稳定锁死在 `#guide`（源于原代码用 `Map` 缓存了元素首次跨界瞬间的静态 `boundingClientRect.top`，且 `scroll-padding-top: 100px` 停靠后 `#guide` 底部仍在观察区上沿 `85px..100px` 内）。已改为 `Set` 实时读取 `getBoundingClientRect().top` 排序、补充多档 `threshold` 并监听 `scrollend`。
3. **`scripts/browser-check.mjs` 外链检查防突发 429 退避**：为原有外链循环中的重试分支补充指数退避等待（保留全部 4 个检查 URL 与 `response.ok()` 断言不变），以应对 GitHub `/blob/` 路由短时并发限流。
